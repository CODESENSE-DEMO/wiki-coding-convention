02. Java / Spring 컨벤션

규칙 JV-01 ~ JV-10최종 개정 2026-09-22

레이어 구조

JV-01표준 레이어와 의존 방향

의존은 항상 아래 방향으로만 흐른다. Repository가 Service를 호출하거나, Controller가 Repository를 직접 호출하는 것을 금지한다.

Controller  →  Service  →  Repository
   (web)       (비즈니스)      (영속성)

JV-02Controller는 얇게 유지한다

Controller에는 요청 검증, Service 호출, 응답 변환만 둔다. 비즈니스 분기·계산 로직이 Controller에 있으면 Service로 옮겨야 한다.

DTO와 Entity

JV-03Entity를 API 응답으로 직접 노출하는 것을 금지한다

Entity 변경이 API 스펙 변경으로 번지는 것을 막고, 지연 로딩 직렬화 사고를 방지하기 위함이다. 응답은 반드시 Response DTO로 변환한다.

나쁜 예 
@GetMapping("/reviews/{id}")
public PrReview getReview(@PathVariable Long id) {
    return reviewRepository.findById(id).orElseThrow();  // Entity 직접 반환
}
좋은 예 
@GetMapping("/reviews/{id}")
public ReviewResponse getReview(@PathVariable Long id) {
    return ReviewResponse.from(reviewService.getReview(id));
}

JV-04DTO 변환 위치

Entity → DTO 변환은 DTO의 정적 팩토리 메서드 from(entity)에 둔다. DTO → Entity 변환은 toEntity()에 둔다. 변환 로직이 Service 본문에 흩어지는 것을 금지한다. 페이징 목록은 Service 에서 PageResponses.from(page).map(Response::from) 으로 변환해 PageResponse<Response> 를 반환한다 (프레임워크 가이드 02).

트랜잭션

JV-05@Transactional은 Service 레이어에만 선언한다

조회 전용 메서드에는 @Transactional(readOnly = true)를 명시한다.

JV-06트랜잭션 내 외부 I/O 금지

트랜잭션 범위 안에서 HTTP 호출(Bitbucket API, vLLM 등)·파일 I/O를 수행하는 것을 금지한다. 외부 호출 지연이 DB 커넥션 점유로 이어진다. 외부 호출은 트랜잭션 밖으로 분리하거나 이벤트/Celery 비동기 작업으로 처리한다.

구현 규칙

JV-07생성자 주입을 사용한다

필드 주입(@Autowired 필드)을 금지한다. @RequiredArgsConstructor + final 필드 조합을 표준으로 한다.

좋은 예 
@Service
@RequiredArgsConstructor
public class ReviewService {
    private final ReviewRepository reviewRepository;
    private final KbResolver kbResolver;
}

JV-08Lombok 사용 기준

애너테이션기준
@Getter, @RequiredArgsConstructor허용 (표준)
@Builder허용 — 필드 4개 이상 객체 생성 시 권장
@SetterEntity에는 금지. 상태 변경은 의도가 드러나는 메서드로 작성
@Data, @ToString(Entity)금지 — 연관관계 순환 참조 및 무분별한 setter 노출

JV-09null 대신 Optional / 빈 컬렉션

컬렉션 반환 메서드는 null 대신 빈 컬렉션을 반환한다. 단건 조회는 Optional을 반환하고, 호출부에서 orElseThrow로 의도를 명시한다. "없으면 404" 가 전부인 조회는 RepositorySupport.getOrThrow(repo, id, "Customer") 를 사용해도 된다. 메서드 파라미터로 Optional을 받는 것은 금지한다.

JV-10JPA 연관관계 기본값

모든 연관관계는 FetchType.LAZY를 기본으로 한다. N+1이 확인된 조회는 fetch join 또는 @EntityGraph로 해결하고, 해결 근거를 PR 본문에 남긴다. 모든 엔티티는 프레임워크 BaseEntity(또는 SoftDeletableEntity)를 상속한다 — 상세는 06. 프레임워크 적용 규칙 FW-02.
