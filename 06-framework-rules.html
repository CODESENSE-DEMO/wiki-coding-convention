06. 프레임워크 적용 규칙

규칙 FW-01 ~ FW-08최종 개정 2026-09-22

본 장은 사내 표준 프레임워크 Union Framework 위에서 애플리케이션을 작성할 때 지켜야 할 규칙이다. 프레임워크가 이미 제공하는 기능을 애플리케이션에서 다시 구현하거나 우회하는 것을 막고, 모든 서비스가 같은 응답·예외·추적·인증 동작을 갖도록 하는 것이 목적이다. 각 구성요소의 상세 사용법은 Union Framework 가이드를 참고한다.

의존성과 부트스트랩

FW-01union-starter 하나만 의존한다

웹 애플리케이션은 io.union:union-starter 를 의존하고, spring-boot-starter-web · spring-boot-starter-data-jpa · spring-boot-starter-security · spring-boot-starter-validation 을 직접 선언하는 것을 금지한다(스타터가 전이 의존으로 가져온다). 프레임워크 버전은 union.version 프로퍼티로 관리한다. Application 클래스에는 @SpringBootApplication 외에 @EnableJpaAuditing, @EnableWebSecurity, @EnableMethodSecurity 를 붙이지 않는다 — 프레임워크 자동 설정과 충돌한다.

나쁜 예 
@EnableJpaAuditing          // 프레임워크가 이미 활성화 → 빈 충돌
@SpringBootApplication
public class CustomerPocApplication { ... }
좋은 예 
@SpringBootApplication
@ConfigurationPropertiesScan
public class CustomerPocApplication { ... }

영속성

FW-02엔티티는 BaseEntity 를 상속한다

모든 @Entity 는 io.union.data.entity.BaseEntity 또는 SoftDeletableEntity 를 상속한다. 생성/수정 일시·작성자 필드(@CreatedDate 등)를 엔티티에 직접 선언하거나 프로젝트별 BaseEntity 를 만드는 것을 금지한다. 감사 이력·법적 보관 의무가 있는 데이터(동의 이력, 거래 이력 등)는 SoftDeletableEntity 를 상속하고 delete() 로 소프트 삭제한다. 물리 삭제(repository.delete)는 보관 의무가 없는 데이터에만 허용한다. 

@Entity
@Table(name = "consents")
@SQLRestriction("deleted = false")
public class Consent extends SoftDeletableEntity { ... }

웹 계층

FW-03컨트롤러는 DTO 를 그대로 반환한다

프레임워크가 반환값을 ApiResponse 로 자동 래핑한다. 컨트롤러에서 ResponseEntity, ApiResponse.ok(...) 로 감싸는 것을 금지한다. 상태 코드가 200 이 아니면 @ResponseStatus 를 사용한다. String 을 반환하면 래핑되지 않으므로 문자열 하나도 DTO(record)로 감싼다. @RawResponse 는 파일 다운로드·외부 규격 콜백처럼 envelope 를 쓸 수 없는 경우에만 허용하며, 사유를 주석으로 남긴다.

FW-04예외는 ErrorCode 로 표현한다

도메인마다 {도메인}ErrorCode implements ErrorCode enum 을 두고, 예외는 BusinessException / EntityNotFoundException 을 상속하거나 Assert 로 던진다(EX-01). RuntimeException 을 직접 상속한 예외 클래스, @RestControllerAdvice 신규 정의(EX-03), @ResponseStatus 를 예외 클래스에 붙이는 방식을 금지한다.

인증 / 인가

FW-05현재 사용자는 @CurrentUser, 인가는 @PreAuthorize

컨트롤러에서 인증 사용자는 @CurrentUser UnionUser user 파라미터로 받는다. SecurityContextHolder 를 직접 조회하거나 Authentication 을 파라미터로 받는 것을 금지한다. 권한 검사는 @PreAuthorize("hasRole('ADMIN')") 를 컨트롤러 메서드에 선언하고, 서비스 본문에서 if (!user.hasRole(...)) 분기로 처리하지 않는다. 개인정보를 반환하는 조회 API 는 반드시 인가 규칙(본인 또는 관리자)을 갖는다 — 인증만 통과하면 누구나 조회 가능한 엔드포인트는 IDOR 로 간주하고 머지 불가로 처리한다. 인증 제외 경로는 코드가 아니라 union.security.permit-all 설정으로만 추가한다. SecurityFilterChain 을 애플리케이션에서 직접 정의하는 것은 개발본부 승인이 필요하다.

나쁜 예 
@GetMapping("/{id}")
public CustomerResponse get(@PathVariable Long id) {
    return customerService.getCustomer(id);      // 인증만 되면 타인의 PII 조회 가능
}
좋은 예 
@GetMapping("/{id}")
@PreAuthorize("hasRole('ADMIN') or #id == T(Long).valueOf(principal.id())")
public CustomerResponse get(@PathVariable Long id, @CurrentUser UnionUser user) {
    return customerService.getCustomer(id);
}

추적 / 이벤트 / 설정

FW-06TraceId 는 프레임워크 것을 쓰고 외부 호출에 전파한다

요청 추적 ID 를 직접 생성하거나 별도 헤더(X-Request-Id 등)를 정의하는 것을 금지한다. 필요하면 UnionContext.getTraceId() 로 읽는다. 다른 사내 서비스를 HTTP 로 호출할 때는 X-Trace-Id 헤더로 전파해야 한다. UnionContext 는 ThreadLocal 이므로 @Async·별도 스레드에서는 값을 인자로 넘긴다.

FW-07트랜잭션 후속 작업은 도메인 이벤트로 분리한다

알림 발송·외부 API 호출·감사 로그 전송처럼 트랜잭션 결과에 따라 실행되어야 하는 후속 작업은 Service 본문에서 try-catch 로 감싸 호출하지 않고(JV-06, EX-02), DomainEvent 를 상속한 이벤트를 DomainEventPublisher.publish(...) 로 발행한 뒤 @TransactionalEventListener 에서 처리한다.

나쁜 예 
customer.block(request.getReason());
try {
    auditClient.send(customer);         // 트랜잭션 내 외부 I/O + 예외 삼킴
} catch (Exception e) {
    log.error("audit 실패", e);
}
좋은 예 
customer.block(request.getReason());
DomainEventPublisher.publish(new CustomerBlockedEvent(customer.getId(), request.getReason()));

// 별도 컴포넌트
@TransactionalEventListener
public void onBlocked(CustomerBlockedEvent event) {
    auditClient.send(event);            // 커밋 이후 실행
}

FW-08프레임워크 설정과 빈 오버라이드

프레임워크 동작은 union.* 프로퍼티로만 조정한다. union.security.jwt.secret 은 소스·설정 파일에 평문으로 두는 것을 금지하며 환경 변수 또는 시크릿 매니저에서 주입한다(LOG-05, GIT 참고). @ConditionalOnMissingBean 으로 열려 있는 프레임워크 빈(GlobalExceptionHandler, PasswordEncoder, AuditorAware 등)을 애플리케이션에서 재정의할 때는 PR 본문에 사유를 명시하고 개발본부 리뷰어를 지정한다. union.web.response-wrapping.enabled=false 로 전체 래핑을 끄는 것을 금지한다.

리뷰 중점 항목 — 자체 BaseEntity/Auditing(FW-02), ResponseEntity 직접 반환(FW-03), RuntimeException 직상속·Advice 신규 정의(FW-04), 인가 없는 PII 조회(FW-05)는 위반 시 머지 불가로 처리한다.
