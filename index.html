코딩 컨벤션 가이드

문서번호 DEV-STD-001 버전 2.5 최종 개정 2026-09-22 관리부서 개발본부

본 문서는 유니온플레이스 개발본부의 표준 코딩 컨벤션을 정의한다. 모든 사내 프로젝트의 신규 코드는 본 컨벤션을 따라야 하며, PR(Pull Request) 리뷰 시 본 문서의 규칙 번호(예: JV-03, FW-02)를 근거로 코멘트를 작성한다. 기존 코드의 일괄 수정은 강제하지 않되, 수정이 발생하는 파일은 컨벤션에 맞추는 것을 원칙으로 한다(보이스카우트 규칙).

사내 Java/Spring 서비스는 표준 프레임워크 Union Framework(io.union:union-starter) 위에서 개발한다. 응답 포맷·예외 처리·요청 추적·JPA Auditing·JWT 인증은 프레임워크가 제공하므로, 본 문서의 관련 규칙(EX / API / FW 장)은 프레임워크 사용을 전제로 기술한다. 프레임워크 자체의 사용법은 별도 문서 Union Framework 가이드(DEV-STD-002, 레포 wiki-union-framework) 를 참고한다.

적용 범위 — 사내 전 레포지토리 (Bitbucket COA, COD, ML, SVC 프로젝트 키 하위 전체). 예외가 필요한 경우 개발본부장 승인 후 레포 README에 예외 사유를 명시한다.

문서 구성

  • CHAPTER 01 네이밍 규칙 패키지 · 클래스 · 메서드 · 변수 · 상수 · DB 객체 이름 규칙 (NM-01 ~ NM-08)
  • CHAPTER 02 Java / Spring 컨벤션 레이어 구조, DTO/Entity 분리, 트랜잭션, Lombok 사용 기준 (JV-01 ~ JV-10)
  • CHAPTER 03 예외 처리 및 로깅 ErrorCode 기반 예외 체계, 예외 삼킴 금지, 로그 레벨 기준, 민감정보 마스킹 (EX-01 ~ EX-06, LOG-01 ~ LOG-05)
  • CHAPTER 04 REST API 설계 규칙 URI 설계, HTTP 메서드/상태코드, ApiResponse 공통 응답, PageResponse 페이징 (API-01 ~ API-07)
  • CHAPTER 05 Git 브랜치 및 커밋 규칙 브랜치 전략, 커밋 메시지 형식, PR 작성 기준 (GIT-01 ~ GIT-06)
  • CHAPTER 06 프레임워크 적용 규칙 Union Framework 를 사용할 때 지켜야 할 규칙 — 의존성, 엔티티, 응답, 예외, 인증, 추적, 이벤트, 설정 (FW-01 ~ FW-08)
  • CHAPTER 07 테스트 코드 작성 규칙 테스트 종류 선택, 네이밍/구성, AssertJ 단언, 테스트 격리, 개인정보 사용 금지, 커버리지 기준 (TEST-01 ~ TEST-08)
