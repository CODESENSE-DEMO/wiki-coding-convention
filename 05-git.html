GIT-02보호 브랜치 정책

main·develop 직접 push를 금지한다. 모든 변경은 PR을 통해서만 머지한다. 머지 조건: 승인 1인 이상 + CI 통과 + CoA 자동 리뷰 코멘트 확인.

COA-247

GIT-04커밋 단위

하나의 커밋은 하나의 논리적 변경만 담는다. 기능 변경과 대규모 포매팅을 한 커밋에 섞는 것을 금지한다. 포매팅·리네이밍만의 변경은 별도 refactor 커밋으로 분리한다.

Pull Request

GIT-05PR 작성 기준

  • 제목은 커밋 제목 규칙과 동일한 형식으로 작성한다.
  • 본문에 변경 배경, 주요 변경점, 테스트 방법, 관련 이슈키를 포함한다. CoA 자동 리뷰가 PR 제목·본문 키워드로 사내 문서를 검색하므로, 핵심 도메인 용어를 본문에 명시한다.
  • 리뷰 가능한 크기를 유지한다 — 변경 500라인 초과 시 분할을 권장한다.

GIT-06머지 방식

feature → develop은 squash merge를 표준으로 한다. release/hotfix → main은 merge commit을 사용해 배포 이력을 보존한다. 머지 완료된 브랜치는 즉시 삭제한다.

참고 — 시크릿(토큰, 비밀번호, 인증서)을 커밋하는 것을 금지한다. 실수로 커밋한 경우 단순 삭제 커밋으로는 이력에 남으므로, 즉시 해당 시크릿을 폐기(rotate)하고 인프라 담당자에게 보고한다.
