07. 테스트 코드 작성 규칙

규칙 TEST-01 ~ TEST-08최종 개정 2026-09-22

본 장은 사내 Java/Spring 프로젝트의 테스트 코드 작성 기준을 정의한다. 테스트는 기능 코드와 동일한 리뷰 대상이며, 본 장의 규칙은 Union Framework 기반 프로젝트를 전제로 한다.

테스트 범위와 구조

TEST-01테스트 종류와 사용 기준

종류대상애노테이션기준
단위 테스트도메인·서비스 로직없음 (POJO) / @ExtendWith(MockitoExtension.class)기본. 스프링 컨텍스트를 띄우지 않는다.
슬라이스 테스트Repository, Controller@DataJpaTest, @WebMvcTest계층 단위 검증에 사용한다.
통합 테스트API 전 구간@SpringBootTest + @AutoConfigureMockMvc주요 시나리오에 한정한다.

단위 테스트로 검증 가능한 로직에 @SpringBootTest 를 사용하는 것을 금지한다. 컨텍스트 기동 비용으로 전체 빌드 시간이 증가하고, 실패 원인 파악이 어려워진다.

TEST-02파일 위치와 클래스 이름

테스트 클래스는 대상 클래스와 동일한 패키지의 src/test/java 하위에 둔다. 이름은 {대상클래스}Test 를 원칙으로 하며, API 통합 테스트는 {도메인}ApiTests 를 사용한다.

좋은 예 
src/main/java/com/unionplace/customer/memo/impl/CustomerMemoServiceImpl.java
src/test/java/com/unionplace/customer/memo/impl/CustomerMemoServiceImplTest.java
src/test/java/com/unionplace/CustomerMemoApiTests.java

TEST-03메서드 이름과 본문 구성

테스트 메서드 이름은 검증 내용을 한국어로 기술한다(언더스코어 허용). 본문은 given / when / then 세 단계로 구분하며, 단계 구분이 자명한 경우 주석은 생략할 수 있다. 하나의 테스트 메서드는 하나의 동작만 검증한다.

나쁜 예 
@Test
void test1() {
    ...  // 등록·조회·삭제를 한 메서드에서 모두 검증
}
좋은 예 
@Test
void 다른_고객의_메모에는_접근할_수_없다() {
    Long memoId = 메모를_등록한다("C-9001");

    assertThatThrownBy(() -> memoService.getMemo("C-9002", memoId))
            .isInstanceOf(BusinessException.class)
            .extracting("errorCode")
            .isEqualTo(CustomerMemoErrorCode.MEMO_NOT_OWNED);
}

단언과 검증

TEST-04AssertJ 사용

단언은 AssertJ(assertThat, assertThatThrownBy)로 통일한다. JUnit Assertions.assertEquals 계열의 신규 사용을 금지한다. 예외 검증은 타입만 확인하지 말고 에러 코드까지 검증한다(EX-01 연계).

검증 대상표준 단언
도메인 예외assertThatThrownBy(...).isInstanceOf(BusinessException.class) + 에러 코드 비교
API 응답jsonPath("$.success"), jsonPath("$.code") 로 표준 응답 포맷 확인
목록/페이징jsonPath("$.data.content"), $.data.page, $.data.totalElements

TEST-05검증 없는 테스트 금지

단언이 하나도 없는 테스트, 실패해도 통과하는 테스트(예외를 try-catch 로 삼킨 테스트)를 금지한다. @Disabled 는 사유와 해제 예정 이슈키를 함께 명시한 경우에만 허용한다.

테스트 데이터와 독립성

TEST-06실행 순서에 의존하지 않는다

테스트는 실행 순서와 무관하게 성공해야 한다. 테스트 간 static 필드 공유를 금지하며, 데이터 변경이 있는 테스트는 @Transactional 롤백 또는 @BeforeEach 초기화로 격리한다. 고정 ID(1L 등)에 의존하지 말고 등록 응답에서 받은 식별자를 사용한다.

TEST-07테스트 데이터에 실제 개인정보 사용 금지

실제 고객 데이터, 운영 DB 덤프, 유효한 주민등록번호·카드번호를 테스트 데이터로 사용하는 것을 금지한다. 샘플 값은 C-9001, 900101-1234567, 010-1234-5678 과 같은 더미 값을 사용하고, 로그로 출력해야 하는 경우 Masker 를 거친다(LOG-05). 외부 연동(KYC, 결제 등)은 실제 호출 대신 @MockBean 또는 스텁 서버로 대체한다.

커버리지와 CI

TEST-08커버리지 기준

대상기준
신규·변경 코드 (service, domain)라인 커버리지 70% 이상 권장
결제·정산·인증·개인정보 처리 로직라인 커버리지 80% 이상 필수
DTO, 설정 클래스, 단순 위임 코드측정 대상에서 제외

커버리지 수치 자체보다 분기(경계값·예외 경로) 검증 여부를 우선 확인한다. PR 본문에는 테스트 실행 방법(mvn clean test 등)과 결과를 기재한다(GIT-05).

리뷰 중점 항목 — 단위 테스트로 충분한 로직의 @SpringBootTest 사용(TEST-01), 단언 없는 테스트(TEST-05), 실제 개인정보 사용(TEST-07)은 위반 시 머지 불가로 처리한다.
