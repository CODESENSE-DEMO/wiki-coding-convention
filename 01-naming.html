01. 네이밍 규칙

규칙 NM-01 ~ NM-08최종 개정 2026-05-12

기본 원칙

이름은 그 자체로 역할과 의도를 설명해야 한다. 주석으로 이름의 의미를 보충해야 한다면 그 이름은 잘못된 것이다. 축약어는 도메인에서 보편적으로 통용되는 것만 허용한다 (id, url, dto, pr 등).

식별자 규칙

NM-01패키지

모두 소문자, 단수형을 사용한다. 회사 도메인 역순으로 시작한다.

com.unionplace.codesense.review
com.unionplace.codesense.kb.resolver

NM-02클래스 / 인터페이스

PascalCase를 사용한다. 역할 접미사를 일관되게 사용한다: Controller, Service, Repository, Config, Dto(요청/응답은 Request/Response). 인터페이스에 I 접두사를 붙이는 것을 금지한다.

나쁜 예 
public interface IReviewService { ... }
public class ReviewSvcImpl { ... }
좋은 예 
public interface ReviewService { ... }
public class DefaultReviewService implements ReviewService { ... }

NM-03메서드

camelCase, 동사로 시작한다. boolean 반환 메서드는 is/has/can으로 시작한다.

의도접두사예
조회 (없으면 예외)getgetReviewById
조회 (없으면 Optional/null)findfindReviewById
목록 조회find~All / listfindAllByRepo
생성create / registercreateKbProject
수정update / changeupdateTrackedBranches
삭제delete / evictevictStaleKb

NM-04변수

camelCase를 사용한다. 한 글자 변수는 반복문 인덱스(i, j)와 람다의 명백한 파라미터 외에는 금지한다. 컬렉션 변수는 복수형으로 짓는다 (reviews, trackedBranches).

NM-05상수

UPPER_SNAKE_CASE를 사용한다. 매직 넘버·매직 스트링을 코드에 직접 쓰는 것을 금지한다.

나쁜 예 
if (retryCount > 3) { ... }
좋은 예 
private static final int MAX_RETRY_COUNT = 3;

if (retryCount > MAX_RETRY_COUNT) { ... }

NM-06DB 테이블 / 컬럼

snake_case 소문자를 사용한다. 테이블은 복수형(pr_reviews), PK는 id, FK는 {참조테이블 단수형}_id(project_id)로 짓는다. 시각 컬럼은 ~_at(created_at, last_used_at), boolean 컬럼은 is_~ 또는 동사형(enabled)을 사용한다.

NM-07TypeScript / React

컴포넌트는 PascalCase 파일명과 일치시킨다(RepoKbConfigTable.tsx). 훅은 use 접두사(useKbPolling), 이벤트 핸들러는 handle~(정의) / on~(prop)으로 구분한다.

NM-08Python

PEP 8을 따른다. 모듈·함수·변수는 snake_case, 클래스는 PascalCase. Celery task 함수명은 동사_목적어 형태로 짓는다 (sync_shared_project, evict_stale_branch_kbs).

참고 — 신규 용어가 필요할 때는 먼저 도메인 용어집(사내 위키 > 개발본부 > 용어집)을 확인하고, 없으면 용어집에 등록한 뒤 사용한다. 같은 개념에 두 가지 이름이 생기는 것을 가장 경계한다.
